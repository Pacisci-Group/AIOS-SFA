# `packages/api` + `packages/shared` — permission & tenancy spine

- **Hierarchy:** `Platform (Super Admin) → Agency (tenant) → Branch → User`.
- **Global guards** (in `app.module.ts`, order load-bearing): `JwtAuthGuard` → `AccessContextGuard` → **`HostTenantGuard`** → `TenantGuard` → `BranchGuard` → `ModuleGuard` → `PermissionsGuard`. `AccessContextGuard` resolves the effective permission set from MongoDB into `request.access`; the rest read from there. The JWT carries **no** permissions.
- **White labelling (hostname → tenant).** Each agency serves the app on its own hostname — a subdomain of `BASE_DOMAIN` or a custom domain — recorded in `agencyDomains` and resolved by `HostTenantResolver`. `HostTenantGuard` then **binds a session to the host it was created on**: a token minted at `texasholdings.com` is refused at any other agency's host, and `PLATFORM_HOST` admits super admins **plus any agency that has no domain of its own yet** (the bootstrap fallback — without it, deploying this locks every existing agency out; it closes as soon as that agency adds a domain). Treat the `Host` header the way `TrustedProxyThrottlerGuard` treats `X-Forwarded-For` — it may *restrict*, never *grant*. Owner-facing settings live at `/settings/{branding,domains,email}` behind `agency:branding:*` / `agency:domains:*` / `agency:email:*`. Outbound links and the email masthead come from `TenantUrlService` + `TenantBrandingService`, never from a global base URL. Per-agency **colours** are explicitly not built yet; `Agency.branding` is shaped to take a `theme` field later. **Logo sizing is fixed in `components/common/BrandMark.tsx`** and must stay in step with the email masthead in `worker/email/templates/layout.ts` — the same uploaded file renders in both. Sizes are in **pixels, not Tailwind's rem scale**: `theme.css` sets `html { font-size: 15px }`, so `max-h-8` is 30px, while the email is a literal `height="32"` that cannot read a CSS variable. **Cap both axes** — height alone lets a wide banner render ~240px wide, past the 224px sidebar and the 56px collapsed rail. App mark 32×48 max (it sits beside the agency name), login lockup 40×160, email 32 tall × 240 wide. **Testing it locally needs three things in `packages/web/vite.config.ts`, all of which broke it when wrong**: `changeOrigin: false` on the API proxy (`true` overwrites `Host` with the proxy target, collapsing every tenant into one), `host: '127.0.0.1'` (Vite's `localhost` default binds IPv6 `::1` only, so an IPv4 `/etc/hosts` entry reaches nothing), and `allowedHosts` (Vite 6 rejects any non-localhost `Host` by default).
- **Data scopes:** `own` · `branch` · `agency`.
- **Module keys** — the enum in `shared/src/enums/module-key.enum.ts`. Toggled per
  agency by Super Admin; disabled ⇒ hidden nav + API 403.
- **Permissions** (`shared/src/permissions/permission.constants.ts`): `"<module>:<read|write>"` + `platform:*` / `agency:*` — 39 strings, described as rows by `PERMISSION_CATALOG` and seeded into the global `permissions` collection. **Relational RBAC**: `rolePermissions`, `userRoles` and `userPermissions` are join collections, written *only* by `RoleAssignmentsService` — a second writer would bypass cache invalidation and the owner-protection checks. Effective set still resolved by the unchanged pure `resolve-permissions.ts` (role perms + grants − revokes, filtered to agency-enabled modules); only the loader is relational, because the permission *strings* are the contract for 91 guard decorators and the whole web app.
- **Default role templates** (`shared/src/permissions/default-role-templates.ts`):
  Agency Owner (agency) · Branch Manager (branch) · Producer (**own**) · CRM
  (branch) · Data Team (agency).
- **Migration key:** `User`/`TenantRecord` carry `legacySmartSuiteId`. The core seed (`src/seed/seed.ts`) is **platform-required data only** — platform super admin, carrier catalog, permission vocabulary. It creates **no agency**: provisioning a tenant (agency + branch + default roles + audit templates — **never users**) belongs to whoever creates one, via the shared `src/seed/provision-tenant.ts`. The **SmartSuite migration** provisions the real agency (`smith-family-agency`); the **demo seed** (`src/seed/demo/`) provisions its own throwaway `demo-agency`.
- **Schemas exist; read path does not.** Mongoose schemas now exist for every domain collection (`src/<domain>/schemas/*.schema.ts`, most extending `src/common/schemas/tenant-record.schema.ts`) and are populated by the SmartSuite→Mongo migration (`src/migration/`). The HTTP **feature controllers are still stubs** (`src/feature-modules/feature.controllers.ts`) returning `{ status: 'ready' }` — add real query services/DTOs there as dashboards get wired.
