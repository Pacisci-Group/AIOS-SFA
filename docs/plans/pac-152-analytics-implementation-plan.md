# PAC-152, part 2 — Analytics page: implementation plan

Ticket: https://linear.app/paciscigroup/issue/PAC-152 (part 2 of the ticket; part 1 is the Data Export page, `pac-152-data-export-implementation-plan.md`).

Paths relative to the AIOS-SFA repo root; `api/` = `packages/api/src`, `web/` = `packages/web/src`, `shared/` = `packages/shared/src`.

## Context

The user wants an **Analytics page** like AgencyZoom's Reports: pick *Sales by Producer / Lead Source / Policy Line / Carrier / Branch / ZIP / CSR*, daily/weekly/monthly summaries, "multi-line by producer", a **Service Center** view (requests by category / policy type / status, opened vs completed over time) and goal pacing. The Agency Owner and the Branch Manager get it by default; it is grantable to anyone through the normal permission matrix. Visual design is ours (theme tokens, light + dark). The user's decisions (7 Oct): **track it on PAC-152**, **new module key `analytics`**, **Sales + Service tabs in v1**, **headline = bound premium with net shown alongside**.

### What exists (verified)

- **One shared sales pipeline.** `api/common/sales-metrics/sales-pipelines.ts`: `SOLD_LINES` (deals → `$lookup policies by dealId` → per-line `{policyType, premium, items, typed}`), `QUOTED_LINES` (quote recaps, embedded `policies[]`), `linesPrefix(match, source, filter, withSource)` (match → optional `sourceStages`/`sourceMatch` — *the lead owns the lead source*, field `sourceId` → lines → `linePremium`/`lineItems`), `policyTypeValues`, `ymdWindow`. `sales-matches.ts`: `resolvePeriod(query, tz) → {period, current, previous}`, `salesScope`, `soldMatch` (scope + `NEW_BUSINESS_MATCH` + `soldDateYmd` window), `quotedMatch`. `household-key.ts`: `HOUSEHOLD_KEY_EXPR`. The Owner view (`api/owner-dashboard/owner-dashboard.service.ts`) is the pattern to copy: `linesPrefix` + `$facet`/`$group`, `soldBy('$producerId'|'$sourceId')`, labels via `displayNamesFor` / `LeadSourcesService.labelsFor`, null rows ("No source"), `owner-dashboard.normalize.ts` (`toTrend`, `closingPct`, `toClosingRatio`, `toLobMix`).
- **Periods.** `api/performance/performance.range.ts`: `resolveRange`/`resolveComparison` (mtd → same days of previous month, etc.), `wholeMonths`, `fromYmd/toYmd/addDays`, `zonedDayStart`, `MAX_CUSTOM_SPAN_DAYS = 366`. Range vocabulary `OWNER_DASHBOARD_RANGE_KEYS` (`shared/domain/owner-dashboard.ts`) = mtd · lastMonth · last3Months · ytd · lastYear · custom.
- **Shared filter DTO** `api/common/dashboard/dashboard-filter-query.dto.ts`: `dashboardFilterFields` {range, from, to, producerIds, leadSourceIds, policyTypes} + `refineCustomRange`; **no `branchId`**; spread the fields to extend (a superRefined schema cannot `.extend()`). Web mirror `web/lib/dashboard-filter-params.ts`.
- **Schemas.** deals: `soldDateYmd`, `premium`, `chargebackAdjustment` (≤ 0), `itemCount`, `policyCount`, `policyTypes[]`, `producerId`, `leadSourceId`, `householdId`, `assignedCrmId` (L274), `branchId` **string**. policies: `policyType`, `carrier` (**free text**; `normalizeCarrier` + `CARRIER_CODE_ALIASES` in `shared/domain/carrier.ts`), `premium`, `items`, `dealId`. quoteRecaps: `quoteDateYmd`, embedded `policies[]` (no carrier), `propertyAddress.zip`, `householdId`, no `leadSourceId`. households: `propertyAddress.zip`, `assignedCrmId`. producerGoals: `{producerId, month 'YYYY-MM', goalPremium}` (premium only; PAC-116 workflow is backlog — rows exist from migration/demo seed only). serviceTickets: **ObjectId** `agencyId`/`branchId`, `category` (`SERVICE_TICKET_CATEGORIES`), `status` (`SERVICE_TICKET_STATUSES`, terminal = resolved|closed), `priority`, `policyType`, `assignedUserId`, `openedAt`, `resolvedAt|null` (**no `closedAt`**), scope via `crm/ticket-scope.ts: buildTicketScopeFilter` (own collapses to branch), window pattern in `management-dashboard.pipelines.ts: overdueTicketsPrefix` + `ManagementDashboardService.overduePrefix` (`zonedDayStart(fromYmd(..), tz)`).
- **Three premium definitions disagree**: Owner/Manager = Σ policy-line premium (fallback deal premium), no chargebacks; Performance = `premium + chargebackAdjustment`; Leaderboard = raw `deal.premium`. → headline **bound premium (Owner definition)**, **net** (`premium + chargebackAdjustment`) alongside.
- **No ticket analytics endpoint exists** (`crm/service-tickets/stats` is own-scope counts only).
- **Permissions.** `ModuleKey` has 14 values (append last — enum order drives catalog `sortOrder`; next = 140/141). Branch Manager template holds leads/clients/deal_audits rw, dashboard/performance/leaderboard/management r, crm_service rw, mailers r, plus `agency:users:read`/`agency:branches:read`. Migration template `api/migrations/20261006111528-data_export_module.js` (catalog rows + enable module where key absent + role grant; constants copied, idempotent). `packages/api/CLAUDE.md` L9 counts "53 strings (14 module keys × …)".
- **Web.** **No chart library** (recharts was removed with the mock); `theme.css` already defines `--chart-1..5` (light + dark) mapped to Tailwind; `components/ui/chart.tsx` absent → `npx shadcn@latest add chart` (installs recharts, `ChartContainer`/`ChartTooltip`/`ChartLegend` bound to CSS vars). ## Design decisions (built to; do not re-litigate)

| # | Topic | Decision |
|---|---|---|
| B1 | Gate | `ModuleKey.Analytics = 'analytics'`, appended last. `analytics:read` is the whole gate; `:write` exists (model needs the pair) and does nothing. Branch Manager template + migration grant; Agency Owner via `grantsAllEnabledModules`; added to `ONBOARDING_DEFAULT_MODULES`. Data Team is *not* granted by default (owner can grant from the matrix). |
| B2 | Engine | Live aggregations, no pre-aggregated store (PAC-134 principle). Every sales number comes through `soldMatch` + `linesPrefix` so the page's totals equal the Owner view's for the same window. |
| B3 | Measures | `SalesMetrics { premium (Σ linePremium), netPremium (Σ deal premium + chargebackAdjustment; null on per-line dimensions), items, deals, policies (typed lines), households (distinct HOUSEHOLD_KEY_EXPR), quotes, quotedPremium, closingPct, closingGap }`. Quotes join producer/leadSource/policyType/branch/zip/csr; carrier has no quote side → `quotes`/closing `null` (N/A). |
| B4 | Dimensions | groupBy ∈ producer · leadSource · policyType · carrier · branch · zip · csr. segmentBy ∈ policyType · carrier · leadSource · producer · branch (≠ groupBy). "Multi-line by producer" = `groupBy=producer&segmentBy=policyType`. Null keys are rows, never dropped ("Unassigned", "No source", "Unspecified", "Unknown carrier", "No ZIP"), so rows always sum to totals. |
| B5 | Carrier | Added to the policy-line lookup via an optional `lineFields` option on `linesPrefix` (default byte-identical to today, so Owner/Manager are untouched). Rows merged by `carrierSlug(normalizeCarrier(raw))`; alias codes (`B4tEH`) fold into their carrier. "Allstate Ins." vs "Allstate" stay separate rows — free text is the honest limit. `carriers` filter via a new `carrierQueryValues()` (name + alias codes), sold side only. |
| B6 | ZIP / CSR | ZIP from the deal's household (`$lookup households` → `propertyAddress.zip`, `$trim`), quotes fall back to their own `propertyAddress.zip`. CSR = `deal.assignedCrmId ?? household.assignedCrmId`. |
| B7 | Time grain | `interval=day|week|month` on the `YYYYMMDD` ints: day = the int; month = `floor(ymd/100)`; week = `$dateTrunc(unit:'week', startOfWeek:'monday')` on a UTC date built with `$dateFromParts` from the int (calendar parts, no zone needed). Tickets bucket their instants with `$dateTrunc(..., timezone: tz)`. Buckets are zero-filled server-side; keys share one format so one fill function serves both. |
| B8 | Compare | `compare=true` runs the same pipeline on `resolvePeriod().previous` and attaches `previous` + `change` per row (`toTrend`, `hasPrior = previous totals.deals > 0`); rows present only in the prior period are kept with zero current. |
| B9 | Range | Add `last12Months` to `OWNER_DASHBOARD_RANGE_KEYS` + `resolveRange` (`wholeMonths(today,-12,12)`) + `resolveComparison` (`wholeMonths(today,-24,12)`). One vocabulary, one filter bar; Owner/Manager chip lists unchanged. |
| B10 | Branch filter | `branchId` query param honoured for **agency-scope callers only** (narrow-only; Data Export D6). Branch Manager stays pinned by the clamp; a producer granted the page gets own sales. Tickets: `buildTicketScopeFilter` → own collapses to **branch** (the CRM rule) — documented, not hidden. |
| B11 | Pacing | `sales/summary.pacing` when the current window lies inside one calendar month and `producerGoals` rows exist for it (narrowed by producerIds/branch/own): `{month, goalPremium, boundPremium, elapsedPct, expectedToDate, projectedPremium, attainmentPct, status: achieved|ahead|behind}`; else `null` + `pacingReason: multi_month_window | no_goals_for_month`. Bound premium = the summary's own figure, so the card and the KPI agree. |
| B12 | Service measures | opened (`openedAt` in window), resolved (`resolvedAt` in window — `closed` without `resolvedAt` is not counted; open question for David), openNow / overdueNow (snapshot, no window), avgHoursToResolve. groupBy ∈ category · policyType · status · priority · assignee · branch. Timeseries follows the page range (the `last12Months` chip gives the AgencyZoom view). |
| B13 | Charts | shadcn `chart` (recharts) with `--chart-1..5`; top-5 + "Other" (`--muted-foreground`) when a series set exceeds 5; prior period drawn in muted; the table is always rendered and is the accessible alternative. Load the `dataviz` skill before writing chart code. |
| B14 | PR split | PR1 = shared + permissions + migration + API + tests + Bruno + `module-catalog.ts` entry (the compile gate). PR2 = chart install + web page + nav/route + docs. |
